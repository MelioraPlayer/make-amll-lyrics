# 多音节、背景人声与对唱

## 拆词的判断顺序

1. 保持原单词拼写，先确定这次演唱实际出现了几个音节。
2. 有清楚的多音节优先分开打轴；字典发音帮助检查，实际唱法决定采用哪种读音。
3. 通常每个单位应包含元音音素；仓库另允许爆破音独立标记，但不必为了显得精细强拆所有辅音。
4. 不超过对应读音通常的音节数；同一元音的 melisma/颤音/拖音不增加音节。清楚重唱一个词/音节是另一个演唱事件，不是任意拆分原词。
5. 切点靠近下一个音节真实起声，不把总时长按字母数、字典连字或等份分配。
6. 单词内部拆分不加空格，词与词之间保留一个独立空格。显示仍是 `being`，不是 `be ing`。

## 例子与例外

| 单词 | 可用拆法 | 需要核对 |
| --- | --- | --- |
| being | be / ing | 两个元音是否清楚分开，不能将一个滑音错当停顿 |
| away | a / way | 开头弱读常很短，重音在 way，不做一半一半 |
| before | be / fore | /f/ 通常属于后半音节；不要 bef / ore |
| beautiful | beau / ti / ful | 后两段常比第一段短，不能按拼写长度切 |
| animal | a / ni / mal | /n/、/m/ 起声作参考，尾部可能拖长 |
| innocently | in / no / cent / ly | 按实际弱读核对，大小写跟随句位 |
| intimidating | in / tim / i / da / ting | 不把两个清楚的音节 tim+i 均摊为一大块 |
| you've / I've / don't | 通常保留整词 | 've、n't 不能仅按缩写词缀当独立音节 |
| fire / hour / every | 依具体唱法 | 不同读音可能合并或舒展，不能用固定模板 |
| you / all / wild | 通常一个音节 | 很长或多音高不自动拆成多个单位 |

`king`、`gure` 等片段是原词的字符分组，不是要单独按新单词发音。保持连写即可；若调整拼写分组，串接后的文本必须与原词逐字符一致。

中文通常逐字。实际连读、儿化、拟声词、多音字和英文夹杂先判断发音，不让模型的罗马化覆盖原字。日语假名、促音等按其语言和仓库当前规则处理，不能照搬英文“每块必须有元音”的算法。

## 主歌词与背景歌词

分类依据是声部功能，不是 `Ohh` 这个词或人声开始时间。

- 主唱独立唱出的 Oh/Ah 可以是主歌词。
- 陪衬和声、回声式回应、与主句叠唱的 ad-lib 可用背景行。
- 背景声部可以先于主句起声或晚于主句收声。TTML 嵌套顺序和屏幕上下布局不是同一个概念：XML 中较早放置不意味着必须显示在上面。
- TTML Tool 中把这一行标为背景行，按标准置于关联主唱行后；导出后用 `ttm:role="x-bg"` 关联到正确主句。不要为了视觉位置把它改成主唱或对唱。
- 独立安排背景单位的 begin/end；不能复用主唱整行范围，也不能让背景音节从 0 秒持续到曲尾。
- 背景行不是译文；背景行自己的翻译必须绑定背景声部，避免覆盖主句译文。
- 用户明确指定 Ohh 放副歌词时保留其选择，并核对关联主行/时标；若与音频明显冲突，说明具体片段后修正。

TTML Tool 通常自动给背景加半角括号，编辑器里不要再手动加一层。直接生成 XML 时最多一组括号，官方解析后应还原为干净文本。背景行内部不要产生空白音节或双重括号。

示意（合成示例，时间仅用于展示结构）：

```xml
<p begin="10.000" end="13.500" itunes:key="L1" ttm:agent="v1"><span begin="10.000" end="12.000">Stay</span><span ttm:role="x-bg" begin="11.500" end="13.500"><span begin="11.500" end="12.300">(Oh</span> <span begin="12.500" end="13.500">oh)</span></span></p>
```

主词 `Stay` 仍在 12 秒结束；容器为了包含背景可以到 13.5 秒。不能为了“背景不延长主唱”把容器写成无法包含子节点的时间；当前播放器是否按容器计算视觉行持续时间，需导入验证。

## 对唱和合唱

- `artists` 元数据描述歌曲参与者；`ttm:agent` 描述某条人声的演唱者，二者不是同一张映射表。制作人/作曲人不自动成为声部。
- 确认有不同演唱者后在 metadata 定义稳定 agent，如 `v1`、`v2`，在各主歌词 `<p>` 引用正确 ID。同一人多段始终用同一个 ID，不为左右交替逐行换人。
- 不根据音高猜歌手性别或身份；不确定是谁时用中性的声部标识，并告知未确认，不虚构姓名。
- 两人轮唱可分行；多人同时唱可按当前格式定义 group agent，或对真实不同唱词保留各自主行及重叠。不要复制一模一样的歌词制造没有声学依据的对唱效果。
- 同一行中途换歌手，按演唱交接拆成合理主行；普通断句仍保留语义完整性。
- 两名主唱的交叠可以真实重叠，单声部自身的倒流不可以；持续和声用背景，而非误用第二主唱。
- 单人回声、混响和声道左右偏移不是对唱证据。不要用任意 `x-duet` 属性替代已核实的 agent 规范。
- 童声、对白或外部采样若确实来自另一位表演者，可考虑独立 agent；只出现一次不意味着必须并入主唱。具体来源不明时不虚构姓名或影视出处。仅凭变调无法确认是否另一人；保留用户选择并说明证据范围，不能把经验建议写成“官方禁止”。

## 人声复核清单

记录每处背景/对唱的起止、主行关联、演唱者证据、是否重叠、原混音是否听得到、分离音轨是否存在伪影。至少检查背景最早开始、最晚结束、两个相邻 Ohh 的分界，以及最后一段长音。模型无法可靠分离时保留较少但可信的单位，不编造多个精确到毫秒的切点。
